# src/email — agent rules

Repo-wide rules in root `CLAUDE.md`. Editing this file → Rule 0 there first (caveman ultra via `caveman:caveman` skill; skill missing = blocked).

## Rules

- **`SocketLabsLib` spec asserting only returned boolean pin nothing about the email.** 4 bugs shipped that way, all under green 100% gate: dead activation URL, stray `}` in subject, leaked `" +` concat syntax in body, hard-coded recipient. Touch any copy → read message back via `sentMessage()` helper in `test/email/SocketLabsLib.spec.mts`, assert `subject` + `textBody` + `htmlBody`.
- **Every value placed in an HTML body must go through `escapeHtml` (`src/private/email/escapeHtml.mts`), and every URL through `htmlLink` (`src/private/email/messageParts.mts`).** Names, error text, ids, codes and the subject in `<title>` reach the HTML part unescaped otherwise, and that was a shipped defect (it was limit L11 in `docs/security.md`): a name like `<script>` became live markup in the mail. The text part and the subject line stay raw, since they are not HTML. A new builder or a new interpolated value needs a hostile-value spec in the `HTML escaping of untrusted values` block of `test/email/SocketLabsLib.spec.mts`. Copy lives in `src/private/email/*Messages.mts`; the class stays a thin dispatcher.
- **Every link base (`linkBase` arg, `APP_DOMAIN`) goes through `httpLinkBase` (`src/private/email/messageParts.mts`) before it is used.** `escapeHtml` is not enough: a `javascript:` base survives escaping and becomes the `href` target. The check is the WHATWG `URL.parse`: only `http:` / `https:`, no user name or password, no control character, whitespace or backslash; a bad base throws `throwInternalError()` and nothing is sent. Never replace it with a prefix test such as `startsWith('http')`: ` javascript:` and `java<TAB>script:` parse to the `javascript:` scheme, and `https://good@evil` starts with `https` yet goes to `evil`. A new builder or send method that takes a base calls it first and gets a hostile-base spec in `describe('SocketLabsLib — link base must be an absolute http(s) URL')`, `test/email/SocketLabsLib.spec.mts`.
- **`createSocketLabsSender` imports NO package.** No env read, no Sentry, no dotenv, no `graphql`. Only `@private/email/socketLabs*.mjs` allowed, and those import nothing external. Env + `loadEnv()` + Sentry text live in `SocketLabsLib`. Peer reach pinned: `PEER_BUDGET` in `test/package/peerReach.spec.mts` (sender + 4 `ISocketLabs*` type files all `[]`). Break it → every consumer of the subpath pays for peers it never asked for.
- `@socketlabs/email` gone (peer + dev + `resolutions` + `src/types/socketlabs-email.d.ts`): latest 1.4.4 → `axios ^0.21.1` → advisories, every consumer failed audit, no fixed SDK. Never re-add it. Client = `src/private/email/socketLabsClient.mts` on `fetch` + `AbortSignal.timeout`, 0 deps. Parts: `socketLabsMessage` (builder), `socketLabsRequest` (checks + headers + body), `socketLabsResponse` (answer → outcome), `SocketLabsSendError`, `withDefined`. Wire format + SDK diffs → `docs/code/email.md`.
- Sender `.d.mts` + `ISocketLabs*` import no package, local structural types. After build: `grep -rn 'from "[^.]' dist/email/*.d.mts` → empty (relative imports only; `SocketLabsLib.d.mts` aside).
- Sender contract, each pinned by `test/email/createSocketLabsSender.spec.mts`: `buildBasicMessage` reads from, fromName, subject, text, html, to, messageId in that order. Message = SDK `BasicMessage` data fields (`messageType: 'basic'`, key absent when no value) → SDK `SocketLabsClient` or SDK-written double passed as `client` still works. NO `try`/`catch` → builder `TypeError`, sync `client.send` throw, throwing `onError` all reject. `onError` typed `unknown`, gets raw rejection by identity, default none. Failure `code` = `rejection.result.name` if string else `'UnknownError'`; never `responseMessage`, `addressResults`, raw error. Defaults `requestTimeout` 120, `numberOfRetries` 3. `RangeError` text names constraint only, never value or key. No `endpointUrl`, no proxy option. Injected `client` ignores `serverId` / `apiKey`.
- **The API key must never appear in a rejection, an error text, a log line or the JSON of an error.** `fetch` puts the whole header value in the `TypeError` text for an invalid header value (`Headers.append: "Bearer <key>..." is an invalid header value.`), so `post()` in `socketLabsClient.mts` drops the caught error and never attaches it as `cause`. The key goes in `Authorization: Bearer` only when it is 61 characters with the first `.` at index 20, otherwise in the body as `apiKey`; it goes nowhere else. Specs: `the key never leaves` and `a key that is no valid header value` in `test/private/email/socketLabsClient.spec.mts`. Never log, never wrap the fetch error.
- **The client can reach exactly one URL, and follows no redirect.** `INJECTION_ENDPOINT` is a constant and `fetch` runs with `redirect: 'error'`, so neither the key nor the mail can be sent to a `Location`. `endpointUrl`, `sleep`, `random` on `ISocketLabsClientOptions` exist for specs only (loopback server, no wait, fixed back-off): the sender never passes them, and they never reach `ISocketLabsSenderOptions` (SSRF). Default endpoint pinned by a `globalThis.fetch` stub spec, never a real call.
- SDK parity, change = consumer-visible → CHANGELOG + `docs/code/email.md`, owner call: retried = timeout + `429` `500` `502` `503` `504` only (not other 4xx, not network error), back-off `min((1 + random) x 1000 x 2^n, 10000)` ms, no `Retry-After`. Only a `200` body is read; every other status → rejection with no `result` → `UnknownError` (a `401` too, on purpose: that is what the SDK gave). `429` retried on purpose, owner decision, SDK never did: rejected req → retry cannot deliver twice. Network error stays unretried (req may have reached SocketLabs → retry may double mail). No `Retry-After`. `Warning` takes first `MessageResults[0].ErrorCode` when known. Client-side check order: credentials, subject, from missing, from invalid, body, recipients none, recipients invalid.
- Specs use a local `node:http` server on `127.0.0.1`, port 0 (`test/helpers/fakeInjectionServer.mts`), fake keys, injected `sleep` / `random`. Never contact `inject.socketlabs.com` or any host. Anything that needs the default endpoint / default sleep → stub `globalThis.fetch`, fake timers for `setTimeout` only.
- `SocketLabsLib` keeps building `this.client` in constructor, passes `client: this.client` per send → `injectClient` seam in `SocketLabsLib.spec.mts` (assigns private `client` after construction) keeps working. Never cache the sender in a field. `sendTemplate` maps `.ok` → boolean; lib's `onError` = `Sentry.captureException(rejection, { extra: { detail: 'Error in sending the email' } })`, raw rejection by identity.
- Callers mail via injected `IVerifyEmailMailer` (`src/lib/access/verifyEmailMailer.mts`), never `new SocketLabsLib()` inline in a guard. Bound default sit behind **process-wide** 15 min per-address-per-template debounce → `src/lib/access/CLAUDE.md`, `test/CLAUDE.md`.
